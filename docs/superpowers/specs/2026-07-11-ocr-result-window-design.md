# OCR 结果窗口美化设计

## 目标

将现有 OCR 结果窗口改造成简洁、现代、易读的工具窗口，同时保留系统原生标题栏、窗口拖动、缩放和位置尺寸记忆能力。界面自动跟随 egui 当前浅色或深色视觉主题，不引入额外主题依赖。

## 范围

本次只调整 OCR 结果视图及其窗口最小尺寸，不改变 OCR 识别、重新截图、复制、关闭和窗口状态持久化的业务流程。

## 窗口

- 保留系统原生标题栏及最小化、最大化、关闭按钮。
- 保留窗口自由缩放以及上次位置和尺寸记忆。
- 默认尺寸继续使用现有的 `500 × 500`，避免覆盖用户已经保存的窗口尺寸。
- 最小内容尺寸从 `200 × 200` 提升到 `440 × 320`，保证标题、状态、文本卡片和操作栏不会严重拥挤。

## 布局

窗口内容采用自上而下的三段式结构，并使用统一的 20 px 外边距：

1. **标题区**
   - 主标题为“OCR 识别结果”，使用更明显的标题字号和加粗字重。
   - 副标题根据状态显示：
     - 识别中：“正在识别图片中的文字…”
     - 成功且有文本：“识别完成 · N 个字符”
     - 成功但无文本：“未识别到文字”
     - 失败：“识别失败，可重新截图后再试”
   - 状态使用克制的语义色；失败状态使用柔和红色，普通状态使用弱化文本色。

2. **文本内容区**
   - 使用带圆角、细边框和内边距的独立卡片承载识别文本。
   - 卡片填充色和边框色从当前 `Visuals` 派生，因此自动适配浅色和深色主题。
   - 文本区域占据剩余可用空间，长文本垂直滚动。
   - OCR 文本保持只读但可选中，使用舒适的正文行高和内边距。
   - 识别中时在卡片中央显示加载指示器和提示。
   - 无文本时显示居中的空状态提示。
   - 失败时在卡片顶部显示错误提示；如果保留有旧识别文本，则旧文本仍可查看和复制。

3. **操作区**
   - 左侧放置次要操作“重新截图”和“关闭”。
   - 右侧放置主操作“复制文本”，通过主题强调色突出。
   - 识别期间所有操作保持禁用，延续当前防御性行为。
   - 无文本时禁用“复制文本”。
   - 复制成功后按钮文案短暂显示“已复制”，为操作提供即时反馈。

## 状态模型

`OcrViewModel` 负责把 `OcrSession` 转换为纯展示数据：

- 当前文本和字符数量。
- 标题区副标题及其语义状态。
- 识别中、失败、空结果等展示状态。
- 复制、重新截图和关闭按钮是否可用。

复制成功反馈属于短生命周期 UI 状态，保存在 `ScreenshotApp` 中并记录截止时间；截止前显示“已复制”，到期后恢复“复制文本”并请求重绘。

## 颜色与视觉

- 不硬编码整套浅色/深色配色，优先使用 `ui.visuals()` 的窗口背景、面板填充、弱文本色、描边和 selection 颜色。
- 卡片圆角为 10 px，按钮圆角为 8 px。
- 主按钮采用当前主题的 selection 背景色与文字色。
- 失败提示使用当前主题错误色，避免固定纯红在深色主题中过亮。
- 不使用渐变、阴影动画或自定义标题栏，以保持跨平台稳定性和较低维护成本。

## 交互与错误处理

- `Esc` 行为不变：识别中忽略，其他状态关闭窗口。
- OCR 失败时显示分类后的现有错误消息，并保留“重新截图”入口。
- 重新截图和关闭沿用现有状态保护，不在视图层绕过业务方法。
- 复制失败时不显示成功反馈；复制成功时显示短暂反馈。

## 测试

- 单元测试覆盖视图模型在识别中、成功、有文本、空结果和失败状态下的副标题、字符数与按钮状态。
- 单元测试覆盖复制反馈文案在截止时间前后切换。
- 单元测试覆盖 OCR 窗口最小尺寸常量，防止布局回退到不可用尺寸。
- 最终运行 `cargo fmt --check`、`cargo test`、`cargo build` 和 `git diff --check`。

## 非目标

- 不增加富文本编辑、文本搜索、导出文件或识别语言选择。
- 不新增图标资源或第三方 UI 库。
- 不修改截图主界面的主题和工具栏。
- 不提供独立主题设置，继续跟随 egui/系统当前主题。
