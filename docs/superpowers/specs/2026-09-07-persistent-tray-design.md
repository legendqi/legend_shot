# Legend Shot 常驻托盘设计

## 目标

让 Legend Shot 启动后常驻 macOS 菜单栏和 Ubuntu 顶栏。应用启动时不自动截图，也不显示截图窗口；用户通过托盘菜单选择“截图”后才进入现有区域截图流程。截图完成、复制、保存或按 `Esc` 取消后，应用回到仅托盘驻留状态；只有托盘菜单中的“退出”会终止进程。

## 范围

本次增加跨平台托盘生命周期、两项托盘菜单、延迟权限检查和新的托盘图标资源，并调整现有截图窗口的关闭语义。保留现有截图、标注、OCR、保存、复制和 `--test` 流程，不增加设置页、全局快捷键、登录时启动或托盘 OCR 入口。

## 技术路线

使用 `tray-icon` 接入当前 `eframe` 应用，不更换窗口框架。

- macOS 要求托盘图标和事件循环位于主线程，因此在 `eframe` 应用创建闭包中创建托盘。
- Ubuntu 上 `eframe` 使用 `winit` 而不是 GTK 事件循环，因此按照 `tray-icon` 官方 `egui` 示例，在独立线程初始化 GTK、创建托盘并运行 GTK 主循环。
- 两个平台都把菜单事件转换成同一组 `TrayCommand`，通过通道交给 `ScreenshotApp`；平台差异封装在托盘模块内部。

参考：

- `tray-icon` 平台与事件循环要求：<https://github.com/tauri-apps/tray-icon>
- `tray-icon` 官方 `egui` 集成示例：<https://github.com/tauri-apps/tray-icon/blob/dev/examples/egui.rs>

## 模块与职责

新增 `src/tray.rs`：

- 定义 `TrayCommand::{Capture, Exit}`。
- 创建“截图”和“退出”两个原生菜单项。
- 加载嵌入二进制的托盘 PNG，并创建 `TrayIcon`。
- 把菜单事件发送给应用命令通道，并请求 `egui` 重绘以唤醒隐藏窗口的事件循环。
- 封装 Linux GTK 托盘线程的启动和停止；封装 macOS 模板图标配置。

调整 `ScreenshotApp`：

- 持有托盘命令接收端和托盘运行时所有权，保证图标在进程生命周期内有效。
- 在 `update` 中排空托盘命令，但不把平台 API 引入截图绘制和标注模块。
- 提供统一的 `begin_tray_capture`、`hide_capture_window` 和 `exit_application` 行为入口。
- 用显式运行状态区分“托盘待机”和“正在截图”，避免用窗口是否可见反推业务状态。

`main.rs` 继续负责进程启动、参数模式选择和 `eframe` 初始化。正常模式创建一个初始不可见的主视口和托盘；`--test` 模式保持原路径，不初始化托盘或 GUI 驻留逻辑。

## 生命周期与数据流

### 启动

1. 解析命令行；若为 `--test`，沿用现有自动截图测试流程。
2. 正常模式加载配置和 OCR worker，创建初始不可见主视口。
3. 创建托盘及菜单，进入 `eframe` 事件循环。
4. 不预先抓屏，不显示截图窗口，也不在启动阶段申请 macOS 屏幕录制权限。

### 开始截图

1. 用户打开托盘菜单并选择“截图”。
2. `tray.rs` 发送 `TrayCommand::Capture` 并唤醒 `egui`。
3. 应用确认当前不在截图流程，防止连续点击重复启动。
4. macOS 在此时检查屏幕录制权限；没有权限时请求授权并留在托盘待机状态，不退出进程。
5. 在窗口仍隐藏时重新抓取所有屏幕，避免把截图遮罩自身捕获进去。
6. 清空上次选择框、临时标注、工具栏和输入状态，重建当前显示器纹理。
7. 恢复各平台已有的截图窗口尺寸与层级配置，显示并聚焦截图窗口。

### 完成或取消

保存、复制、双击复制、工具栏退出按钮以及普通截图状态下的 `Esc` 都调用 `hide_capture_window`：

- 隐藏主视口，而不是发送 `ViewportCommand::Close`。
- 清理本次截图的瞬时状态并返回托盘待机。
- 保留配置、OCR worker 和托盘，允许下一次截图重新使用。

OCR 结果窗口和 OCR 重新截图保留现有业务语义；只有从普通截图流程返回托盘的路径改为隐藏主视口。实施时需避免把 OCR 结果窗口的“关闭”误改为退出整个常驻进程。

### 退出

托盘菜单“退出”发送 `TrayCommand::Exit`。应用先通知 Linux GTK 线程结束，再关闭主视口并退出 `eframe` 事件循环。托盘对象随运行时释放，顶部图标消失。

## 权限与错误处理

- macOS 屏幕录制权限从启动期检查改为首次及后续截图动作前检查。
- 首次请求权限后不假定权限立即生效；本次截图终止并保持托盘可用，用户授权后再次点击“截图”。
- 抓屏失败时保持窗口隐藏和托盘可用，向标准错误输出包含上下文的错误消息，不留下透明全屏窗口。
- 托盘初始化失败属于正常模式的启动失败：返回清晰错误，避免进程运行但没有任何可操作入口。
- 重复点击“截图”在已截图或正在启动截图时被忽略，防止重入和重复抓屏。
- Linux 托盘线程退出失败不得阻塞 UI 退出；停止信号采用非阻塞发送，线程资源随进程结束回收。

## 图标设计与资源

采用已确认的 A“聚焦框”方向：四个圆角取景角围绕一个实心中心焦点，纯单色、透明背景、不含文字。

- 以确定性 SVG 作为母版，几何对齐整数或半像素网格，保证小尺寸锐利。
- 导出 16、20、24、32、64 和 128 px PNG；运行时使用适合托盘 API 的高分辨率 PNG，由系统按显示密度缩放。
- macOS 将图标标记为模板图标，由系统根据菜单栏背景自动着色。
- Ubuntu 使用高对比单色透明 PNG，确保 GNOME 顶栏浅色和深色主题下可辨识。
- 重点检查 16–20 px 下四角不粘连、中心点不消失、笔画粗细一致。

资源放在现有 `src/icon/` 目录中，文件名使用 `tray-focus` 前缀。SVG 是可维护源文件，PNG 是构建时直接嵌入的运行时资源。

## Ubuntu 构建与运行要求

`tray-icon` 在 Linux 上依赖 GTK3 以及 AppIndicator 实现。更新构建脚本和 README，说明 Debian/Ubuntu 构建环境需要 GTK3、`libxdo` 和 `libappindicator3` 或 `libayatana-appindicator3` 的开发包。桌面环境还必须提供 AppIndicator/StatusNotifier 支持；标准 Ubuntu GNOME 通常由对应扩展提供。

这些依赖只放在 Linux 目标依赖区，避免影响 macOS 构建。交叉编译脚本需同步补齐目标架构的 pkg-config/sysroot 查找说明。

## 测试与验收

### 自动验证

- 单元测试覆盖托盘菜单 ID 到 `TrayCommand` 的映射。
- 单元测试覆盖应用运行状态转换：待机 → 截图、截图 → 待机、任意状态 → 退出。
- 单元测试确认普通完成/取消动作请求隐藏窗口，而不是关闭应用。
- 单元测试确认 `--test` 模式不初始化托盘且保持原有行为。
- 运行 `cargo fmt --check`、`cargo test`、`cargo check` 和 `git diff --check`。

### macOS 手工验收

- 启动后仅显示菜单栏图标，没有 Dock 图标和截图窗口。
- 点击图标显示且仅显示“截图”“退出”。
- 首次选择“截图”才触发屏幕录制权限请求；拒绝或尚未授权时应用仍驻留。
- 授权后再次选择“截图”可正常进入选区；保存、复制或 `Esc` 后回到托盘。
- 浅色、深色菜单栏及 Retina 显示下图标清晰。
- 选择“退出”后进程和菜单栏图标都消失。

### Ubuntu 手工验收

- GNOME 顶栏显示图标，点击后出现“截图”“退出”。
- 截图完成或取消后继续驻留，可连续执行多次截图。
- 缺少所需系统依赖时，构建或启动错误信息可定位问题。
- 选择“退出”后 GTK 托盘线程和应用进程结束。

## 非目标

- 不增加开机登录时自动启动。
- 不增加全局快捷键、设置窗口、托盘 OCR 或截图历史。
- 不重构为 Tauri/TAO，也不分别维护两套完整原生托盘实现。
- 不改变现有截图标注功能和 OCR 结果 UI。
- 不在 Windows 上承诺本轮托盘支持；代码结构保留后续扩展空间。
